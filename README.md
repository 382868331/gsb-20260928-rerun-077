# RaftLab 分布式系统实验室

一个在单个 Go 进程中运行多个虚拟 Raft 节点的交互演练。节点之间没有共享内存中的“上帝视角”：每个节点只根据自己的任期、投票、日志，以及通过可配置网络收到的 `RequestVote`、`AppendEntries` 消息改变状态。

## 内容

- 领导者选举：随机选举超时、任期、一票限制、多数派投票。
- 日志复制：领导者追加、冲突回退、多数派提交、跟随者提交推进。
- 网络模拟：定向延迟、链路断开、分区时立即丢弃在途消息、恢复后重新同步。
- 确定性复演：虚拟时钟、固定 seed 和带时间戳的场景 JSON；事件顺序可保存后重放。
- 正确性测试：少数派不能提交；恢复网络后旧领导者不能覆盖已确认日志。
- 投递前暂停与分叉实验：在任意在途消息上设暂停点，在该点克隆出两个独立实验，分别调整投递顺序或网络连通并对比节点确认记录。共同前缀一致，分叉后队列、时钟和决策完全独立。
- 暂停点持久化：实验以 `experiments/*.json` 保存（共同前缀场景 + 每次分支决策），后端重开后自动重建，可追溯旧领导者恢复与少数派隔离组合下的每个决定。
- 视图防崩溃：空在途队列始终输出 `[]` 而不是 `null`；前端带错误边界，损坏的 JSON 复演只显示错误，不替换当前工作区。
- 分叉韧性：分叉保存失败会明确报错且暂停点与工作区保持不变；单个实验文件损坏或数据缺失时仍保留其记录与错误提示，其余实验照常列出和操作。
- 首次决定分歧分析：任选两条实验轨迹比较，区分「仅消息到达顺序不同」「节点已作不同确认」「资料尚未完整」三种情况，并给出首个分歧点的时间、节点、日志下标与消息定位。
- 对照实验：可从一条分支中任选一次网络干预（链路/延迟/分区/恢复），建立「不施加该干预」的对照轨迹，检验它是否足以解释目标分歧；多个干预叠加时必须显式选择归因对象，不会默认归给最后一次操作。保存后的对照不可改写，可一键回到对应分支的消息与节点记录。

## 运行

```bash
cd backend
go run .
```

另开终端：

```bash
cd frontend
/做题/.tools/env20260928/frontend/node_modules/.bin/vite
```

打开 Vite 输出的本地地址。前端会把 `/api` 代理到 `http://localhost:8080`。

## 验证

```bash
cd backend && go test ./...
cd frontend && /做题/.tools/env20260928/frontend/node_modules/.bin/tsc --noEmit
```

页面中的绿色 `#index` 表示该节点本地已经提交；红色表示只是未确认日志。已提交视图由各节点自己的 `commitIndex` 和本地日志汇总展示，模拟器不会用共享状态替节点宣布成功。
